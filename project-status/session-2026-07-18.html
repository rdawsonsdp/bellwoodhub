Headline

Agents became instructable. An agent used to be a code artifact — its scope was a hardcoded stream enum and a time window over recent mail. It is now configured by one plain-English instruction, matched semantically across the entire archive. The first agent built this way had no stream routing at all and still produced four cited findings on its first live run against a real mailbox.

Evidence — the agent works

The Google Security agent's first live run, against a real mailbox of 5,400+ messages. Zero messages reached it through stream routing; every finding came through the instruction:

"RED: Account-recovery attempt fired twice today — plus a breach notice and five unconfirmed sign-ins still open"

  • Two identical critical recovery alerts the same day — cited, with the action that closes them
  • A password-breach notice from 11 July, still unresolved
  • Five routine sign-in alerts grouped into one point rather than listed separately
  • Connected the repeat pattern to the recovery attempt — judgment, not summary

What we learned

Concrete instructions retrieve well; abstract ones return noise. Measured on a live mailbox: "invoices and payment requests" and "meeting invitations" returned precisely the right mail. "Anything urgent that needs a reply from me" returned marketing copy — it matched the emotional register of hype, not urgency. This single finding shapes how every user must be taught to write instructions, and it is now the central rule of the test plan: name a thing you could search for.

A score-based warning for bad instructions was built and then deleted the same evening — correct invoice results and pure junk both scored 0.41, so any threshold that catches the junk mislabels the good results. Shipping it would have been worse than shipping nothing.
